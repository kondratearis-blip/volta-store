# KOKORO — заказы, курьеры, кухня

Рабочая система KOKORO (kokoro.com.kg): сайт для гостей, панель менеджера, приложение курьера, экран кухни,
страница продуктов шефа и база Supabase со всей логикой.

> **Откуда этот код.** 21.11.2026 снят с рабочего сайта kokoro.com.kg и рабочей базы Supabase:
> на GitHub до этого лежала только ранняя версия от 27.10 (она осталась в истории этой ветки).
> Полный исходник проекта был на компьютере разработки и в GitHub не отправлялся — см. «Чего здесь нет».

## Что где

| Адрес | Файлы | Для кого |
|---|---|---|
| `/` | `site/index.html`, `assets/js/app.js`, `order.js`, `i18n.js`, `history.js`, `motion.js` | Гости: меню, доставка или самовывоз, оплата по QR с чеком, статус заказа с обратным отсчётом, чат, оценка. Русский и кыргызский. Устанавливается как приложение (`site.webmanifest`, `sw.js`) |
| `/admin` | `site/admin.html`, `assets/js/admin.js`, `cashbox.js`, `receipt-ocr.js`, `receipt-check.js`, `zip.js` | Менеджеры: заказы за день, статусы, проверка чеков (распознавание прямо в браузере), курьеры, чаты, касса и отчёты, настройки, две точки |
| `/courier` | `site/courier.html`, `assets/js/courier.js` | Курьеры: вход по личному коду, смена, свободные заказы точки, «Забрал — еду» / «Доставил», карта и порядок объезда, заработок, Telegram-бот для передачи места |
| `/cook` | `site/cook.html`, `assets/js/cook.js` | Кухня точки: «Принят» → «Готовим» → «Готово» (курьер и гость сразу видят «Готово») |
| `/kitchen` | `site/kitchen.html`, `assets/js/kitchen.js` | Шеф: продукты кухни и цены. Вход по личной ссылке `kokoro.com.kg/kitchen#XXXX-…`, ссылку выдаёт функция `kitchen_new_link` |

Общее: `assets/js/data.js` — всё о KOKORO в одном месте (состав комбо, телефоны, точки, часы, статусы);
`api.js` — запросы к базе; `supabase-lite.js` — мини-клиент Supabase; `config.js` — адрес базы и публичный ключ;
`map.js`, `maps.js` — карты (Leaflet + OpenFreeMap) и ссылки в 2GIS; `chat.js` — окно чата.
`assets/vendor/` — сторонние библиотеки (GSAP, Leaflet, MapLibre, Tesseract) — не править.

### База — `supabase/`

- `schema.sql` — **полный снимок схемы рабочей базы**: 21 таблица, 137 функций, 13 триггеров, 32 правила доступа,
  права, хранилища файлов. Проверено: в чистой базе восстанавливается без ошибок, все 137 функций совпадают с рабочими байт в байт.
- `seed-settings.sql` — настройки (`order_settings`, `branch_settings`) и справочник продуктов кухни.

Заказов, курьеров, админов и переписки в репозитории нет — это личные данные клиентов, они хранятся только в Supabase
(проект `kokoro`, `sbqkzfytezlunhukfdzz`). Вся бизнес-логика — в функциях базы: цена заказа, распределение по курьерам,
доставка, «дождь», номера заказов за день и т. д. Сайт только вызывает их.

## Как вносить правки

- **Тексты, состав комбо, телефоны, точки** — `site/assets/js/data.js`.
- **Цена, доставка, приём заказов, QR-код, время ожидания** — в панели `/admin` → «Настройки», без кода.
- **Вид и поведение страниц** — файлы из таблицы выше.
- **Логика в базе** — найти функцию в `supabase/schema.sql` (`create or replace function public.<имя>`),
  поправить и выполнить этот блок в Supabase → SQL Editor. Это сразу меняет рабочую базу — сначала проверяйте.

Посмотреть сайт у себя: `node scripts/serve.mjs` → http://localhost:5180 (`/admin`, `/courier`, `/cook`, `/kitchen`).
Он работает с **настоящей** базой: тестовый заказ попадёт в панель менеджера.

## Публикация

Сайт работает на **Cloudflare** (папка `site/`, заголовки безопасности — `site/_headers`).
Раньше выкладывали с компьютера разработки (`scripts/deploy.mjs`, в репозиторий не попал).
Как подключить этот репозиторий, чтобы изменения в `main` выкладывались сами, — пошагово в **[CLOUDFLARE.md](CLOUDFLARE.md)**.

Новый внешний сервис (карты, аналитика, API) заработает только после добавления его адреса в `Content-Security-Policy` в `site/_headers`.

## Чего здесь нет (осталось на компьютере разработки)

Код ссылается на файлы, которых нет ни на сайте, ни в GitHub:

- `specs/007…026` — описания задач и решений (дизайн, приложение для магазинов `specs/025`, курьеры, кухня, чаты);
- `scripts/` — `deploy.mjs`, `serve.mjs`, проверки `check-admin.mjs`, `check-cook.mjs`, `check-sql.mjs`, `test-client.mjs`, `test-receipt-check.mjs`;
- `supabase/*.sql` — исходные миграции с комментариями (`couriers.sql`, `kitchen.sql`, `auto-dispatch.sql`, `mini-app.sql`, `rain.sql` …).
  Их итог целиком сохранён в `supabase/schema.sql`, но комментарии и порядок изменений — только там;
- серверные части снаружи сайта: приём сообщений Telegram-бота (`kokoro_tg_update`) и отчёты о погоде
  (`kokoro_weather_update`) присылает какой-то внешний обработчик — вероятно, Cloudflare Worker. Его код снаружи не виден.

Если тот компьютер доступен — отправьте папку проекта целиком в этот репозиторий, ничего не потеряется.
