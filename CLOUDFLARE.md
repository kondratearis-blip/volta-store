# Подключить GitHub к сайту kokoro.com.kg (Cloudflare)

После подключения каждое изменение в ветке `main` само попадает на kokoro.com.kg за 1–2 минуты —
без ручной выкладки с компьютера.

**Почему нужен новый проект.** Сайт выкладывали с компьютера командой (`scripts/deploy.mjs`, «Direct Upload»).
К такому проекту Cloudflare не даёт подключить GitHub — только создать новый проект из репозитория
([документация](https://developers.cloudflare.com/pages/get-started/direct-upload/)). Поэтому: создаём новый проект,
проверяем его на временном адресе и переносим на него домен. Старый проект не удаляем — это запасной вариант для отката.

## Шаг 1. Создать проект из репозитория

Cloudflare → **Workers & Pages** → **Create** → вкладка **Pages** → **Import an existing Git repository** → **GitHub**.
Если Cloudflare попросит доступ к GitHub — разрешите приложению Cloudflare доступ к репозиторию `kondratearis-blip/-`
(«Only select repositories» → выбрать его).

Настройки сборки:

| Поле | Значение |
|---|---|
| Project name | `kokoro-site` (любое; станет адресом `kokoro-site.pages.dev`) |
| Production branch | `main` |
| Framework preset | `None` |
| Build command | пусто (если поле обязательно — `exit 0`) |
| Build output directory | `site` |
| Root directory | пусто |

**Save and Deploy** — первая сборка занимает около минуты. Публикуется только папка `site/`:
`supabase/`, `scripts/` и README в интернет не попадают.

## Шаг 2. Проверить на временном адресе

Откройте `https://kokoro-site.pages.dev` (или тот адрес, что показал Cloudflare) и проверьте:
главную, `/admin` (вход менеджера), `/courier`, `/cook`, `/kitchen`.
Сайт работает с **той же рабочей базой**: если оформите тестовый заказ — он появится в панели, отмените его там.

## Шаг 3. Проверить старый проект

Откройте старый проект сайта в Workers & Pages.

- Если это **Pages** и в нём есть вкладка **Functions** со списком адресов — остановитесь и напишите Claude:
  там может работать приём сообщений Telegram-бота или погоды, их нужно перенести до смены домена.
- Если это **Worker** (а не Pages) — можно подключить GitHub прямо к нему (Settings → Builds) без переноса домена;
  напишите Claude имя Worker'а — нужен файл настроек с этим именем.

## Шаг 4. Перенести домен

Делайте в тихий час, когда нет заказов: на 1–5 минут сайт может не открываться.

1. Старый проект → **Custom domains** → `kokoro.com.kg` → **Remove**. То же для `www.kokoro.com.kg`, если он там есть.
2. **DNS → Records** домена: если осталась запись `CNAME kokoro.com.kg → <старый-проект>.pages.dev` — удалите её.
3. Новый проект → **Custom domains** → **Set up a custom domain** → `kokoro.com.kg` → **Activate**
   (запись DNS Cloudflare создаст сам). Затем так же `www.kokoro.com.kg`, если он был.
4. Откройте kokoro.com.kg и проверьте главную, панель и страницу курьера.

**Откат:** те же шаги наоборот — убрать домен из нового проекта и вернуть в старый.

## Как это работает дальше

- **Изменение в `main` → сайт обновляется сам.** Ход сборки — в проекте → **Deployments**.
- **Claude работает в своих ветках** (`claude/...`). Для каждой Cloudflare сам делает предварительную ссылку (Preview) —
  можно посмотреть правку до выкладки. Влили ветку в `main` — правка на живом сайте.
  Preview тоже работает с рабочей базой.
- **Откатить неудачную выкладку:** проект → Deployments → прошлая версия → **Rollback to this deployment**.
- Ветки других проектов в этом репозитории (Hunter Quest, магазин и т. д.) собираться не будут — в них нет папки `site`;
  их ошибки сборки ни на что не влияют. Чтобы не видеть их, Settings → Builds → Branch control → Preview branches → Custom.
- Выкладка с того компьютера (`deploy.mjs`) после переноса домена на сайт **не попадает** — она идёт в старый проект.
